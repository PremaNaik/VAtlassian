This folder combines three snapshots into one tree. Local checks pass
(`npm run verify`: 2,306 backend tests, 320 frontend tests, smoke 283/283, UI
build). That is not live Jira acceptance; see the checklist at the end.

## Changes made during the merge

- **Migration renumbered.** `v144_webauthn_lock` became `v184_webauthn_lock`
  because v144 is taken on the mainline. It uses `CREATE TABLE IF NOT EXISTS`,
  so a site that already ran the old id is unaffected.
- **Admin reset for the biometric lock.** The lockout message sends people to
  an administrator, but before-sprint had no reset, so a locked person could
  never sign again. Added `admin:resetBiometricSigning`
  (`src/usecases/adminRecovery.js`): another administrator only, ledger event
  `WEBAUTHN_RESET` written first, then unlock and revoke devices. Also added a
  card on Credentials & recovery and tests.
- **Biometric pre-check fix.** The pre-check in `approval.challenge()` called
  `controlledAuthenticationMethod()`, which throws on a non-signature policy,
  so `challenge()` failed with SERVICE_UNAVAILABLE. It now compares
  `required_assurance === 'BIOMETRIC'` directly.
- **Lockfile URL fix.** Both frontend lockfiles pointed
  `@atlaskit/tmp-editor-statsig` at a tarball name that does not exist
  (`tmp-editor-statva-147.1.0.tgz`), so `npm ci` failed. Corrected.
- Added `test/credential-setup.test.js`. Updated the Credentials page test
  and `test/migrations.test.js` (last id is now `v184_webauthn_lock`).

## Sprint features (rebuilt)

None of the three snapshots contained the sprint code, and it was not in any
searchable chat. It was rebuilt from the design recorded in the earlier sprint
`manifest.yml` (app `5c96b956…`). The manifest entries match that file
exactly; the code behind them is new and needs live testing.

- **Readiness** (`src/lib/sprintReadiness.js`). A sprint item is ready only
  when it and every descendant (children and sub-tasks, up to 4 levels and 500
  nodes) are covered by an active baseline, either their own or as a node of
  an active tree baseline, and none is DRIFTED, DECIDING, RESTORING or ERROR.
  A tree too big to read in full is not ready.
- **Sign and start sprint** (`src/lib/sprintStart.js`). Allowed only on a
  future sprint, only when every item is ready, and only for a holder of the
  **"Sprint owner"** role (Approver roles page, all work item types) for the
  board's project. The server re-checks readiness, and the readiness hash must
  match what the signer saw. The signature is an authenticator code. The
  ledger entry `SPRINT_START_SIGNED` and a signed operation row are written
  before Jira is asked to start the sprint as the app.
- **Sign and complete sprint.** Allowed on a running sprint. The signer
  chooses the backlog or a future sprint of the same board. The open item set
  and destination are signed (`SPRINT_COMPLETE_SIGNED`). Then
  `jobs/sprintWorker.js` (queue `va-sprint-queue`) moves the open items and
  closes the sprint. If the sprint has gained open items since signing,
  nothing is moved or closed and it must be signed again.
- **Detective control** (`src/triggers/sprint-event.js`). A sprint started or
  closed without a matching signed operation is written to the ledger
  (`SPRINT_STARTED_UNSIGNED` / `SPRINT_CLOSED_UNSIGNED`) and raised as an alert
  work item (`SPRINT_UNSIGNED`).
- **Screen:** `frontend/src/sprint/SprintReadiness.tsx`, opened from "Start
  Sprint" in the sprint card's ••• menu on the backlog.
- **Storage:** `va_sprint_operation` (migration `v185_sprint_operation`).
- **Tests:** `test/sprint.test.js` (18) and `frontend/test/sprint.test.mjs` (4).

Choices made while rebuilding:

- **Authenticator code only.** Sprint signing does not offer the biometric
  device check.
- **Role name.** The signing role is fixed as "Sprint owner" (`SPRINT_ROLE`).
- **Manage sprints.** To take Jira's own Start and Complete buttons away,
  grant the Jira "Manage sprints" permission only to the app's role on each
  board. The app starts, moves and closes as itself.
